# SpeedMeasurement · 局域网测速站

Rust（axum）写的本地测速服务。电脑开热点、手机连上后打开网页，测延迟 / 抖动 / 下载 / 上传，
并把不同位置（隔不同墙体材质）的结果记录下来做对比。全程只在局域网内，不依赖外网。

## 运行

```bash
cargo run --release
# 或直接跑已构建的二进制
./target/release/SpeedMeasurement
```

默认监听 `0.0.0.0:8080`，可用 `PORT=9000` 覆盖。

启动后会打印手机可用的地址，例如：

```
手机访问（与电脑同一热点/局域网）：
  http://192.168.137.1:8080
```

### 手机连接

1. 电脑开启热点（或手机与电脑连同一个 WiFi）
2. 手机浏览器打开启动日志里的地址
3. 点「开始测试」

> 若手机打不开：检查电脑防火墙是否放行 8080/TCP（Windows 首次运行会弹窗询问，选允许）。
> 电脑有多个网卡时启动日志会列出全部地址，逐个试即可。

## 测速口径

| 项目 | 方法 |
|------|------|
| 延迟 | 32 次 `GET /api/ping`，丢弃前 3 次连接开销，取剩余 29 个样本的中位数 |
| P95 | 上述样本的 95 分位（最近秩） |
| 抖动 | 上述样本的标准差 |
| 丢包 | 失败请求数 ÷ 29 个有效样本 |
| 下载 | 4 并发流式读取，8 秒窗口内的平均速率 |
| 上传 | 4 并发 POST 4 MiB，8 秒窗口内的平均速率 |

速度单位 Mbps（bits/s ÷ 10⁶）。

## 墙体 / 多径对比方法

把手机依次放到不同点位：同一房间、隔一堵混凝土墙、隔木门、隔玻璃……每个点位连测 3 轮，
保存时按「点位-轮次」填标签（如 `P1-R2`）。历史列表里的百分比条形 = 下载速率相对最快一次的保留率；
盲区判定看 PING 中位数、P95 与丢包率是否同向劣化，单个指标异常需结合 3 轮重复确认。

## 数据

结果存于 `data/results.json`，每条含 `label`、`ping_ms`、`p95_ms`、`jitter_ms`、`loss_pct`、
`down_mbps`、`up_mbps` 与时间戳；删除该文件即可重置。旧版本没有 P95 / 丢包字段的记录仍可正常读取（缺省为 0），
文件解析失败时启动日志会告警，不会静默当成空数据。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 页面 |
| GET | `/api/info` | 本机局域网地址列表 |
| GET | `/api/ping` | 204，用于 RTT |
| GET | `/api/download?bytes=N` | 流式输出 N 字节 |
| POST | `/api/upload` | 流式接收并统计字节数 |
| GET/POST | `/api/results` | 列出 / 保存结果 |
| DELETE | `/api/results/{id}` | 删除一条结果 |
