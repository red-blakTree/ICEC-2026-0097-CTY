## 2. P0 · 阻断项（不解决就不能定级）

**P0-1 SIR 只在 7 个点位有值，且不是逐轮读数。**
方案已把 SNR 改为 SIR（未找到能在手机上测 SNR 的应用），但 PureHub 只在「扫描」页给 SIR，且每个点位只拍到一个时刻：有值的是 T5-02 / T5-03 / T5-05 / T5-06 / T5-07 / T5-08 / L1-01（−9.9 / −35.3 / −9.9 / −33.4 / −13.3 / −21.5 / −9.2 dB），只有两个基准点没有。因此 RQ1 的「SIR 与延迟是否同向劣化」只能在 7 个点上做，且不能逐轮配对。报告需写明 SIR ≠ SNR，负值按界面原样记录、不做符号修正。

**P0-2 RSSI 不是逐轮读数，且 PureHub 自身在同一分钟内就前后矛盾。**
每个点位只有 1 个时刻的 1–3 张 PureHub 截图，3–4 轮测速共用这一个值。更麻烦的是同一分钟两个页面的读数对不上：

- 电梯内同一分钟（11:55）三张截图：扫描 −65 / −76 dBm、概览 −81 dBm，极差 16 dB；
- 防火门 12:16 概览 −69 dBm vs 扫描 −80 dBm（11 dB）。

这意味着截图不能当作「同一时刻的单点快照」，RSSI 的 ±2–3 dB 不确定性在这里已放大到 10 dB 以上。**本核查统一取「概览」作为连接态 RSSI**（`signal.csv` 保留两页原文，`measurements.csv` 的 `rssi_dbm` 用概览值），但这条规则必须在报告里写明。另需注意：`rssi_dbm` 取概览、`sir_db` 取扫描，二者不是同一页/同一秒；T5-05 的（−81, −9.9）实际来自相差 16 dB 的两张图（−65 扫描页给 SIR，−81 概览页给 RSSI），SIR 只能作点位级解释性指标，不能当作与该行 RSSI 同刻的配对读数。

**P0-3 两个基准点没有 PureHub 读数。**
T5-01（514 门前）与 T5-04（电梯门口）是方案指定的开阔参照点，但都没有 PureHub 读数，按方案的参照点无法计算 ΔRSSI。方案 §6.3 另有 fallback（未指定参照点时取 8 点中 RSSI 中位数最高者），因此可退化为以 T5-02（−63 dBm）为参照，给出「相对 T5-02」的衰减；但 T5-02 不是开阔基准，RQ3 只能得到退化结果，且必须在报告中注明参照点变更。

**P0-4 宿舍未测，点位不齐。**
实采 9 个点位（教学楼 5F 8 个 + 图书馆 1F 1 个），宿舍整块缺失，与方案「8 点含宿舍」的设定不一致。报告必须写明覆盖范围，不能默认代表两栋楼。

## 3. P1 · 口径偏差（可在报告中说明后使用）

- **P1-1 热点配置偏离方案**：安全性「打开」（开放网络，非 WPA2）、BSSID `a2:1e:09:30:b6:a3` 为本地管理的随机 MAC（方案要求 `cloned-mac-address permanent`）、信道固定 7（方案要求 1/6/11 中较空闲者）。前两项影响可追溯性，第三项意味着结果不能直接与信道 1/11 的现场比较。
- **P1-2 截图里的「距离」不是测距值**：PureHub 的距离与 `d = 10^((−40 − RSSI)/20)` 的自由空间换算在 2.4G 上吻合到 5% 以内（−65 → 17.4 m、−72 → 38.9 m、−74 → 49.0 m、−78 → 77.6 m、−80 → 97.7 m、−82 → 123.0 m），且随频段变化（−72 dBm 时 5G 显示 16.4 m、2.4G 显示 38.9 m），即它是 RSSI/频段的换算显示，不是测量，不能填 `distance_m`，也不能跨频段比较。方案要求的现场估测距离仍然缺。
- **P1-3 轮次不齐**：两个基准点各 1 轮，其余点位 3–4 轮（514 3 轮、507 4 轮、图书馆 4 轮、电梯 / 拐角 / 楼梯 / 防火门各 3 轮）。方案要求每点 3 轮取中位数、单次读数不得判定——基准点按方案不具备判定资格。另：514 门前基准是整场第一条记录（11:39:48），P95 78.4 ms、抖动 23.3 ms 均高于同区域的 514 教室门（30.4 ms）与电梯口（24.7 ms），疑含首轮冷启动开销，不宜与其他点位直接比较。
- **P1-4 上传失败未计入丢包**：id=5 与 id=7（均在 T5-03）的 `up_mbps = 0` 但 `loss_pct = 0`；口径把上传失败与丢包分开算，报告里不能拿 `loss_pct` 当「无异常」的证据。
- **P1-5 电梯内首轮是离群值且无复测**：P95 = 473.8 ms、抖动 115.1 ms（后两轮 75.0 / 35.6 ms），按方案 §7 应加测确认，目前没有复测记录。3 轮跨度 7 分 22 秒，很可能包含轿厢运行，不是静态点位。
- **P1-6 吞吐与 RSSI 不单调**：−80 dBm（512 拐角）下载 7.4–9.4 Mbps，低于 −69 dBm（防火门）的 12.3–15.9 Mbps，而 −83 dBm（507 后）只有 3.1–8.3 Mbps。开放网络下吞吐受同频干扰与设备状态影响大，不能当作衰减的代理指标。
- **P1-7 位置照元数据口径不一致**：5 张 OnePlus 原图的机身水印为 11:59–12:16（与采集时间吻合），但 EXIF `DateTimeOriginal` 统一为 14:31–14:42（晚于采集约 2 小时），属导出/转存时被重写，**EXIF 不能用作时间佐证**，应以水印和测速记录为准。新增的 9 张「今日水印相机」照片没有 EXIF，时间/地点只来自水印（11:41–12:36），与测速时间线吻合，但属第三方 App 自证、非独立元数据；`in_elevator` 11:50 那张的水印地点显示「地点获取中」，缺 GPS 佐证。另：`signal.csv` 中 11:55:29/32/35 的秒级时间无法从现有文件独立核验（截图只到分钟、无 EXIF），按分钟级使用。

- **无热点重启、无漫游**：7 张概览页的 BSSID 均为 `a2:1e:09:30:b6:a3`、信道 7（2442 MHz）；扫描页不显示 BSSID，只显示 SSID 与信道 7。方案 §2.2 的「BSSID 变化即作废」未触发。
