# AI 提问排障对话记录

7 张关键提问的对话截图。每张记录的是：我提出具体问题、把已知条件和数据边界一起给出 → AI 定位根因并给修正方案 → 结论回到报告或代码里核对。

不是把 AI 当答案机：能落回报告和代码的才留下；被数据推翻的判断按真实条件改写，而不是留着好看的解释（第 4 张）。

| 截图 | 排障问题 | AI 回答与落地 |
|---|---|---|
| [1.png](1.png) | 课题 3 走廊衰减怎么归因（T5-02 同走廊直线无遮挡、开口在 514 侧） | 删掉「过道开口泄漏」，改为「507 端附加损耗 / 驻波节点」，并给每 2 m 停一次的补测 SOP |
| [2.png](2.png) | 课题 8「还能用什么更好的算法」 | 单特征 AUC 0.981 / 0.996，判断算法不是瓶颈；推荐先做 LR / 线性 SVM 对照，否决堆模型 |
| [3.png](3.png) | 课题 8「四个基线做最小对照」 | v6 规则 vs LR / LinearSVC / RBF-SVM / RF；RBF-SVM 折外 94.2 %，收益来自绕开 v6 固定门限 |
| [4.png](4.png) | 课题 8 测试数据的真实采集条件（口袋 / 他人手机 / 相同姿势） | 推翻 AI 先前「机型运动读数有偏」的判断，按真实条件重写结论 |
| [5.png](5.png) | 课题 8「这个加速度是含 g 的」——含 g 就能直接用吗 | 含 g 只保证瞬时 `‖a‖ ≈ 9.8`，手持摆动时窗均值会落到 4.2 / 12.6 / 14.5；用 0.5 s 均值轨迹（图 9）证明问题不在「有没有 g」，而在「这段数据能不能定出 g 的方向」，据此引入逐样本重力解耦 |
| [6.png](6.png) | 课题 8「补录要怎么做」——要补什么、怎么补 | 给出 Phyphox 同步录加速度 + 陀螺仪的 SOP、每段开头 10 s 静止的标定理由、20 段 / 15 分钟的最小补录清单（2 人 × 2 机 × 5 状态 × 2 次）与「统一平端手机」替代方案 |
| [7.png](7.png) | 课题 8「Phyphox 里勾哪些传感器」 | 勾加速度计 + 重力传感器、不勾陀螺仪（手机自带重力方向，比陀螺仪积分更稳），采样率保持最快；导出前静置看重力三轴模长是否 ≈ 9.8，CSV 须同时出现 `Acceleration` 与 `Gravity` 两组列 |

前 4 张偏算法选型与结论复核，后 3 张转到**采集协议**：从「换什么算法」改问「怎么让数据支持这个算法」——含 g 的数据怎么解耦、补录流程怎么设计、传感器勾哪几项。
