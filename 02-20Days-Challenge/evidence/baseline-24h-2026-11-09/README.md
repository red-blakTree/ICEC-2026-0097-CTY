## 2. 时间线与日志结构

- 11-08 11:22:36 网页点“重置测试”开始计时（`POWER.CSV` 第一条 `uptime=1748`，`e_mwh` 归零）
- 11-08 11:22:36 – 11-09 11:22:36 逐小时拍照，共 24 张，跨度 24.00 h
- 11-09 00:22:36 **缺 1 张**：23:22:36 → 01:22:36 间隔 2 h；`POWER.CSV` 同时刻无 `CAPTURE` 行，但 5 分钟 `SAMPLE` 连续 → 单次拍照失败，不是复位/死机

```text
uptime_s,event,window_s,v5_mv,i_ma,p_mw,e_mwh
```

- `uptime_s` 的 0 点是 11-08 10:53:28；墙钟 = 10:53:28 + `uptime_s`
- 322 行：26 条 `CAPTURE` + 296 条 `SAMPLE`（每 5 分钟一条，24.00 h 主体无间断；末尾还有复位后约 1.15 h 的残行，`max uptime=90547 s`，不计入 24 h 主体）

- `i_ma = 45`：固定模型值（240 MHz 空转 + AMS1117 静态电流），**不是实测电流**；`e_mwh` 到 11:22:36 为 5400 mWh，纯模型推算
- 最后两行 `uptime 4 / 6` 属于复位后的新会话，与 24 h 主体无关

## 3. 能证明 / 不能证明

**能证明**

- 24.00 h 的采集循环连续：24 张逐小时照片 + 296 条 5 分钟 `SAMPLE`，只在 00:22 缺 1 张。
- 拍照不依赖 WiFi：08:20 前后网络中断期间，08:22 / 09:22 两张照片仍在、`SAMPLE` 连续。

**不能证明**

- 真实电流/能量：`i_ma = 45 mA` 是模型值，实测常开空闲是 `0.09 A`（2 倍），本日志是低估值。
- 深睡/峰值/电池电压：本目录没有这些数据；24 h 表端点见另一目录。

## 4. 复现

```bash

for i in $(seq -w 1 26); do curl -s -O http://192.168.16.101/IMG_000$i.jpg; done

```
