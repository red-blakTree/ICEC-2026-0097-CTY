# viewer 主基线：WiFi 常开空闲与开网页录屏（2026-11-10 21:02–21:25）

> 数据性质：**表直读 + 录屏**（5 V 输入侧）。
> 结论：viewer（WiFi 常开 + 每小时一张）稳定后 `0.09 A / 5.04 V / 0.45 W`；开网页后 `0.11–0.14 A`。这是 viewer 常开空闲（P6）的直接读数。

## 1. 现场

- 固件：`esp32cam-viewer`（主基线，WiFi 常开 + 网页 + 每小时一张），2026-11-10 晚间构建后烧录。
- 判定依据：电流持续 `0.09 A`——省电版在 15 min 窗口关闭后读 `0.00 A`，只有 viewer 会把 WiFi 一直挂着。
- 供电：充电宝 → USB 电压电流表 → ESP32-CAM 5V/GND；量的是表后整条路径（含 AMS1117、摄像头、SD）。
- 时间：照片水印 2026-11-10 21:02；表计时 `0:08`，即该次上电约 20:54（读数已稳定）。
- 表上读数（见 `frame_meter_zoom.jpg`）：`5.04 V / 0.09 A / 0.45 W / 累计 64 mWh / 计时 0:08`。
- 录屏：`video_20261110_212524772.mp4`（21:25，49.4 s / 720×1280 / 无音轨）；表计时 `0:31`，与 21:02 的 `0:08` 对得上。

## 2. 自洽性核对

| 核对项 | 算法 | 结果 |
|---|---|---|
| A 与 W 是否一致 | `0.09 A × 5.04 V` | `0.454 W` ≈ 表显 `0.45 W`，这一刻两个字段自洽 |
| 瞬时值与累计值是否一致 | `64 mWh ÷ 8 min` | `0.48 W` → 平均 `≈0.095 A`，与瞬时 `0.09 A` 差 1 个字，说明这 8 min 一直停在这一档 |
| 量化误差 | 0.01 A 分辨率 | `0.09 A` 对应 `90 ± 5 mA`（±5 %） |

## 3. 能得出什么

- viewer 常开空闲 ≈ `90 mA`，与省电版窗口空闲段 `0.09–0.10 A`（另一轮独立测量）在 1 个字内一致：**两条固件“开着 WiFi 什么都不干”的底值相同**，跨固件对比成立。
- 与固件模型 `kModelIdleMa = 45 mA` 比，实测是它的 **2 倍**；差值主要来自模型不含 WiFi 电流。
- 因此 [baseline-24h-2026-11-09](../baseline-24h-2026-11-09/README.md) 的 `POWER.CSV`（45 mA、`v5_mv=-1`）对 viewer 是**低估值**；按 `90 mA` 常开外推约 `2.16 Ah/天`，模型口径约 `1.08 Ah/天`，量级差 2 倍。这只是外推，不是 24 h 实测。

## 4. 不能得出什么

- **不是 24 h 连续记录**：单个时刻 + 8 min 累计，覆盖不到每小时一次的拍照；拍照瞬时在这块 0.01 A 表上不可分辨。
- **电压口径不可直接混用**：本轮 `5.04 V`，另一轮 `4.90 V`，差 3 % 来自表/线压降不同；`mAh` 与平均电流不受影响，换算 `Wh` 时按当轮电压。
- **单次读数不等于统计结论**：要证伪 45 mA 模型，得连续对齐 `POWER.CSV` 与表读数，而不是拍一张照片。
- 照片只能证明“这一时刻表上显示 0.09 A”，不能证明 8 min 里没有低电流间隙——间隙由累计量反推排除到 ±1 个字。

## 5. 开网页：0.09 → 0.11–0.14 A

同一轮上电里，浏览器打开 viewer 网页、翻图时录了 49 s：

| 状态 | 电流 | 说明 |
|---|---|---|
| 未开网页 | `0.09 A` | 稳定空闲 |
| 开网页 / 拉图 | `0.11–0.14 A` | 视频 + 现场读数 |
| 峰值（现场观察） | 约 `0.15 A` | 抽帧未必能抓到瞬态 |

- 这段证明“WiFi 页面请求会把基线从 0.09 A 抬到 0.11–0.14 A”，与省电版窗口段 `0.12–0.19 A` 同量级。
- 视频的 `W` 字段是时段平均、`A` 是瞬时；功率/能量一律用 `A × V` 或累计 `mWh ÷ 时间`，不用 `W` 反推电流。
